# 第一版需求

产品名 DeskFrzA。目标为可以在 GitHub 开源并提供下载的 Windows 桌面图标布局软件。

用户确认的范围：

1. 相同屏幕配置精确恢复作为验收底线；图标跟随原显示器为核心特色。
2. 手动保存和恢复，恢复前自动备份并可撤销。自动恢复、断屏自动迁移留到后续。
3. 所有布局在记录区直接列出，连续编号，支持选用、重命名和删除；旧格式记录兼容保留。
4. 原有图标恢复优先，新图标保持原位，冲突时同屏就近移开；删除项目跳过。
5. 分辨率、缩放不同需适配，优先保持网格行列和原顺序，避免重叠和越界。
6. 容量不足时暂停，保持桌面原状。
7. 自动排列开启时提示，由用户点击关闭，不静默改设置。
8. 通栏横带保留布局操作；记录面板顶部为当前屏幕配置，下方展示选用编号与全部布局列表。
9. 层间距默认 48px，可调整；象牙白主体，柔和过渡配色，避免说明性小字堆积。
10. 标题栏滚动触发吸顶，内容正常滚动；不是整块面板覆盖。

实现选择：原生 WPF 窗口承载 WebView2；C# 负责 Windows DisplayConfig / Shell COM、纯布局规划和本地持久化；HTML/CSS/JS 负责 dashboard。复用同一回环服务支持浏览器开发验证。

不猜测硬件身份，不恢复已断开的显示器，不改变显示设置；预检与执行之间校验当前屏幕配置和图标集合/位置。图标身份使用 Shell 的桌面绝对解析名称，支持系统项目与用户/公共桌面项目，避免显示名称重复导致误匹配。

2026-10-11 记录改版：桌面图标位置、数量或屏幕配置偏离选用布局后，询问是否保存为新记录；拒绝不覆盖原记录。每 4 秒读取状态，窗口隐藏或弹窗打开时暂停询问。成功恢复后使用实际落位作为变化比较基准，避免适配、新图标或删除图标造成反复误报。

2026-10-11 界面调整：删除记录后按保存时间重新连续编号，选用关联仍以内部 ID 保持；左上角 DeskFrzA 逐字循环输入，完成后瞬间清空；移除版本展示和页脚标语，改为浅黄色 GitHub 主页链接 https://github.com/flackoye。屏幕比例明确标示 Windows 显示缩放。


2026-10-11 迁移简化（替代之前的多屏合并与就近补位逻辑）：

- 普通多屏保存、恢复、记录管理保持原有行为。迁移只支持切换前所有图标在一屏，目标默认新主屏。
- 先整体平移，所有图标使用相同位移；DPI 不触发两轴独立拉伸。放不下时只能整体等比例缩小，用户明确确认。
- 全局形状优先。不拆散分组，不逐图标塞空位，不合并多屏图标。仍有重叠/越界/新增图标冲突则暂停。
- 首次使用无需历史记录：运行期间保留最近一次观察到的切换前布局。仅可保护应用实际观察过的现场。
- 多屏都有图标时提示一句原因，“保留更改 / 撤销切换”。撤销需同一组显示器仍连接，且保留了原生显示配置；先验证配置、保留备份，再恢复主屏和图标。
- 能原样迁移：“取消 / 迁移”；需缩小：“取消 / 缩小并迁移”；无法迁移：“知道了”。不展示预检、适配、局部重排方案。
- GitHub 更新功能保留；正式 Release 检查、安装包校验、确认升级和重启。


2026-10-12 默认单屏与拔屏保护（替代第一版自动恢复暂缓的范围）：

- 记录按保存模板的屏幕数分为单屏和多屏；三屏以上也属于多屏，不限定某两款设备。
- 首次使用必须选择或保存一个默认单屏模板。单屏不假定为笔记本内屏，可为任意主机的唯一显示器。
- 两屏仍连接但图标集中在一屏时，可以单独保存单屏模板；复制旧记录时保留原记录及当前多屏选用状态。
- 只保存一个默认记录 ID，切换默认项不删除其他模板；默认项不可直接删除。
- 原生后台监听及轮询检测单屏，等待配置稳定两秒，启动单屏同样恢复一次。避免覆盖后续手动调整；重新接入多屏再断开时重新触发。
- 自动恢复按唯一屏幕匹配或适配；沿用新图标、删除图标、容量、自动排列和落位验证规则，不改变显示设置或图标尺寸/网格设置。
- 失败只提示原因及“重新恢复”，不自动反复重试。后台执行不依赖前端窗口可见性。关闭应用后的桌面无法实时保护，重新打开可恢复。

2026-10-12 分组编号：单屏、多屏分别从 01 开始；删除只重排所属分组，默认项与选用项仍使用内部 ID 关联。提示中的编号附带单屏/多屏名称。

2026-11-13 恢复逻辑修订：保留现有界面流程。首次从双屏现场保存默认单屏模板时，以完整现场记录变化基准；完整回到已有历史时自动识别，部分模板匹配不吞掉后续手动改动。单屏模板及其成功撤销不重排无关屏幕；撤销按本次实际位移范围回退，旧备份保留完整恢复兼容。历史空副屏断开而全部模板图标原屏仍连接时，允许在原屏恢复。手动成功保存/恢复消费当前自动恢复任务；失败保留应急备份，不循环重试。

2026-11-13 托盘与后台开销：窗口 X 隐藏到系统通知区域，双击或右键“打开 DeskFrzA”唤回，右键“退出”完全结束。隐藏/最小化持续两秒后释放网页界面，重开重新加载后台状态，未确认的页面输入和预览重置；后台桌面观察、自动恢复及撤销保护继续运行。必须统计本程序及所属WebView2子进程，记录真实内存与重开耗时，不承诺未测硬件上的固定内存上限。

2026-11-13 使用模式修订（替代上文默认驻留及强制单屏初始化规则）：

- 默认关闭后台挂载，仅作为手动布局存储库；窗口 X 真正退出，不留托盘或后台观察进程。
- GitHub 图标左侧增加同风格、无可见文字的小开关，悬停或键盘焦点显示同字体的小面板：“是否开启后台挂载：当前为否/是”。
- 选择即刻保存；旧记录没有该设置时默认关闭，重新打开保留已选状态，其他设置保存不覆盖此项。
- 开启后才驻留托盘、监测图标与屏幕变化；关闭时停止观察，清理待自动恢复、切屏提醒和通知状态。开启动作不修改当前桌面。
- 图标稳定变动后通过 Windows 系统横幅询问是否保存；发送提醒不显示/激活应用。点击通知才打开对应保存确认；未点击、超时、关闭通知均不代表同意保存。
- 通知去重由原生进程负责；与已有弹窗冲突时延后处理。切屏提醒与图标保存提醒分别传递，旧切屏状态不能劫持新保存提醒。
- 默认单屏模板不强制；保存单屏记录不自动设默认。用户自行设置后，只有后台开启才执行原有单屏自动保护。

2026-11-13 通知与插拔边界补充：

- 旧托盘气泡在用户实机验收时没有显示，改用按数据目录注册的Windows Toast；待处理改动同时显示静态托盘橙点。托盘提供测试通知和系统提交状态，不把API调用成功当作横幅验收成功。
- 通知只对当前开启的驻留会话有效；关闭模式、退出清通知，旧通知不能冷启动默认数据目录或后台服务。
- 单屏自动保护等待屏幕配置和图标位置稳定，执行后不因手动拖动反复触发；失效的主屏切换源随断开/组合变化清理。
- 多屏自动选历史、接屏自动恢复双屏、分散多屏图标自动合并均未实现；DP/HDMI只按Windows实际报告的屏幕状态统一处理。具体条件见RESTORE.md。
